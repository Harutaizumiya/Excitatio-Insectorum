# 01 需求基线文档

## 1. 产品定位

本系统是面向班级课堂管理场景的 Web 应用，核心目标是通过「座位管理 + 课堂积分 + 随机点名 + 班级大屏」形成轻量级课堂激励闭环。

系统包含三类使用主体：

- 班主任：负责班级治理和全部管理能力。
- 任课教师：通过移动端快捷页面进行积分操作和随机点名。
- 大屏设备：绑定具体班级，仅用于只读展示和视图交互。

MVP 重点保证：

1. 班级、学生、教师、座位、积分等基础数据完整。
2. 任课教师在课堂上可以快速操作。
3. 大屏可以实时响应积分、座位和随机点名事件。
4. 权限边界清晰，历史数据可追溯。

## 2. 用户与角色

### 2.1 班主任 HEAD_TEACHER

每个班级只允许存在一个有效班主任。

权限：

- 管理班级基础信息。
- 管理学生。
- 管理任课教师。
- 创建任课教师邀请链接。
- 管理班级积分规则。
- 查看全部积分流水。
- 创建任意正负积分记录。
- 撤销任意积分记录。
- 编辑和恢复座位布局。
- 管理最多两个班级大屏设备。
- 查看后续统计入口。

### 2.2 任课教师 SUBJECT_TEACHER

由班主任创建。

登录方式：

1. 班主任创建任课教师。
2. 系统生成一次性邀请链接。
3. 任课教师通过手机浏览器打开链接。
4. 邀请链接验证通过后绑定教师身份。
5. 系统签发长期登录凭证。
6. 后续教师直接访问移动端教师页面。

权限：

- 查看本班学生和座位。
- 查看本班全部积分流水。
- 使用班级共享积分规则。
- 创建正分或负分。
- 创建自定义积分，自定义积分必须填写详细原因。
- 撤销自己创建的积分记录。
- 使用随机点名。
- 不可创建、修改或删除积分规则。
- 不可管理学生、教师、座位和大屏设备。

### 2.3 大屏设备 DISPLAY_DEVICE

一个班级最多绑定两个有效大屏设备。

设备与班级一一绑定，每个设备拥有独立设备凭证。

权限：

- 读取当前班级。
- 读取当前座位布局。
- 读取 Top3。
- 读取进步趋势。
- 接收实时事件。
- 本地切换视图。
- 本地进入全屏。
- 不允许修改任何业务数据。

## 3. 核心业务规则

### 3.1 班级

- 一个班级对应一个有效班主任。
- 一个班级允许多个任课教师。
- 一个班级最多绑定两个有效大屏设备。
- 任课教师权限只对其绑定的班级生效。
- 所有业务数据必须包含班级作用域。

### 3.2 学生

学生属于一个班级。

状态：

- ACTIVE：当前在班。
- INACTIVE：已经离班。

学生离班时：

- 保留所有积分流水。
- 保留所有历史座位版本。
- 当前座位中移除。
- 当前排行榜中排除。
- 不进行物理删除。

### 3.3 座位布局

教室采用固定网格模型。

定义：

- Classroom 存储 `gridRows` 和 `gridCols`。
- 网格中的一个 Cell 最多存在一个 Seat。
- Seat 可以为空座位。
- Seat 最多绑定一个学生。
- 讲台固定显示在网格上方，MVP 不作为数据库实体。
- 教师可以在固定网格范围内添加、删除和拖动座位。
- 不采用自由像素坐标。

编辑流程：

1. 班主任进入座位编辑模式。
2. 在本地完成多次拖拽和调整。
3. 点击“保存布局”。
4. 后端保存一份完整新版本。
5. 当前布局版本切换到新版本。

历史要求：

- 保留全部历史版本。
- 恢复历史布局时复制目标版本生成一个新版本。
- 不覆盖、不删除旧版本。

### 3.4 积分规则

积分规则属于班级。

规则字段至少包含：

- 名称。
- 分值 `delta`。
- 描述。
- 是否启用。

积分支持：

- 正分。
- 负分。

例如：

- 回答问题：+2
- 积极参与：+1
- 帮助同学：+2
- 课堂纪律：-2
- 迟到：-1

班主任维护规则，任课教师只使用规则。

### 3.5 自定义积分

班主任和任课教师均可创建自定义积分。

要求：

- `delta` 必须为非 0 整数。
- 支持正负数。
- 必须填写详细原因。
- 建议原因最少 10 个字符。
- 后端必须再次校验。

### 3.6 积分流水

积分流水永久保存。

普通记录：

- studentId
- classId
- operatorId
- subject
- ruleId，可为空
- delta
- reason
- type = NORMAL
- createdAt

撤销规则：

- 不删除原流水。
- 生成一条反向流水。
- 新流水 `type = REVERT`。
- 新流水关联 `revertedRecordId`。
- 班主任可撤销本班任意可撤销记录。
- 任课教师只能撤销本人创建的记录。
- 同一记录只能被撤销一次。

### 3.7 排行榜

MVP 固定统计周期：本周。

大屏显示：

- Top3。
- 进步趋势。

隐私要求：

- 大屏不显示学生具体积分。
- Top3 只显示姓名和名次。
- 进步趋势显示姓名和排名变化。

Top3：

- 统计本周积分流水 `SUM(delta)`。
- 按总积分降序。
- 取前三名。

进步趋势：

当前策略：

`上周排名 - 本周排名`

例如：

- 上周第 15 名。
- 本周第 6 名。
- 展示 `↑9`。

算法必须由后端策略层实现，避免算法写死在前端。

### 3.8 随机点名

任课教师可以发起随机点名。

MVP：

- 从当前 ACTIVE 学生中随机抽取。
- 返回结果给教师端。
- 同时向本班所有在线大屏广播。
- 大屏高亮被点名学生。
- 高亮数秒后自动恢复。
- 本轮已点名单可以先保存在教师端本地状态。
- MVP 不保存点名历史。

### 3.9 大屏绑定

流程：

1. 大屏打开绑定页面。
2. 后端生成短期 6 位绑定码。
3. 大屏展示绑定码。
4. 班主任在管理端输入绑定码。
5. 后端确认班级与设备绑定。
6. 给设备签发长期设备凭证。
7. 后续设备自动进入对应班级展示页。

设备凭证：

- 长期有效。
- 可主动吊销。
- 每个设备独立。
- 班主任可查看设备状态和最后在线时间。

## 5. 非功能要求

### 安全

- 所有管理 API 必须认证。
- 所有业务请求必须校验 class scope。
- 密码只保存 hash。
- 邀请 Token 和设备 Token 的服务端持久化值保存 hash。
- 敏感操作记录 operatorId。
- 大屏 Token 只拥有只读业务权限。

### 一致性

- 积分写入与撤销必须使用数据库事务。
- 座位版本保存和 Classroom 当前版本切换必须在同一事务完成。
- 实时事件只作为通知渠道。
- HTTP API / 数据库状态是最终事实来源。

### 可追溯性

以下数据保留历史：

- 积分流水。
- 积分撤销流水。
- 座位布局版本。
- 学生离班状态。
- 教师关系。
- 大屏设备绑定和吊销记录。

### 性能目标

MVP 目标：

- 单班 30～60 名学生。
- 每班最多 2 块大屏。
- 单学校数十到数百班级。
- 普通 API P95 目标 < 500ms（同地域部署条件下）。
- 实时事件正常网络条件下目标 < 1s 到达大屏。
