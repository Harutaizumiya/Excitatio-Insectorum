# 教师端小程序迁移实施记录

日期：2026-10-08。需求依据：[PRD](教师端迁移微信小程序%20PRD.md)。本记录区分代码交付和微信平台验收，不代表已发布或已通过微信审核。

## 已确认的规则

- 专用邀请、服务端微信凭证交换、教师确认后直接绑定原 `User.id`，不增加班主任审批。
- 不按姓名、昵称、头像合并身份；禁止自动覆盖绑定或换绑。恢复入口指导联系班主任核验，未提供越权全局重置功能。
- 保留旧 Web 邀请和教师入口。撤销班级关系继续使用现有会话吊销范围，未承诺仅吊销一个班的会话。
- 独立 `apps/teacher-miniprogram`，Taro 4.3.0 / React 18.3.1；Web 保持原有运行时。
- 退出或会话失效时清除学生及喊话正文缓存；未知写结果只保留按教师/班级隔离的去重键回执，重登仅可查询，不能用已删除的内容重新提交。

## 新增接口

所有路径以 `/api/v1` 为前缀，成功响应沿用 `{ data }`；分页沿用现有分页 envelope。

| 路径                                                                        | 请求/结果                                                                 | 权限与状态                                                           |
| --------------------------------------------------------------------------- | ------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| `POST /auth/wechat/login`                                                   | `{ code }` → `BOUND`、TokenPair、teacher；或 `UNBOUND`、ticket、expiresAt | 仅服务端换取 OpenID；不接受客户端身份字段                            |
| `GET /auth/wechat/invitations/:token/preview`                               | teacher、classroom、headTeacher、expiresAt                                | 仅合法专用邀请；不消费                                               |
| `POST /auth/wechat/bind`                                                    | `{ ticket, token }` → `BOUND`、TokenPair、teacher、classroom              | 短期 ticket、邀请、唯一绑定及会话在事务中处理                        |
| `POST /classes/:classId/teachers/:classTeacherId/wechat-invitations`        | miniProgramPath、codeImage、expiresAt                                     | 当前班主任；真实小程序码生成成功后才保存邀请；重发撤销旧未用专用邀请 |
| `POST /classes/:classId/teachers/:classTeacherId/wechat-invitations/revoke` | `{ revoked: true }`                                                       | 当前班主任；不撤销任课关系                                           |
| `GET /classes/:classId/score-events/by-key/:businessKey`                    | 既有 ScoreEventResult                                                     | 当前有效班级关系且为原操作者；未知/非本人结果返回 404                |
| `GET /classes/:classId/announcements/by-key/:idempotencyKey`                | 既有 Announcement                                                         | 当前有效班级关系且为原教师；未知/跨班结果返回 404                    |

教师列表新增 `wechatBound` 和 `wechatInvitationExpiresAt`，不返回 OpenID。旧 Web 邀请消费拒绝小程序专用邀请。既有积分业务键继续唯一；重放必须匹配班级、操作者、学生与事件参数，否则返回 409；匹配重放不再次广播。

喊话结果核查沿用原服务的 7 天记录保留策略。未查询到未知写结果不等于证明原请求从未提交；退出后的最小回执不支持补发，需保留待核查状态或联系班主任核验。

## 运行与发布准备

- 开发：`pnpm dev:teacher`；构建前设置 HTTPS `TARO_APP_API_ORIGIN`，再运行 `pnpm build:teacher`。将 `apps/teacher-miniprogram` 作为微信开发者工具项目打开，生成目录为 `dist/`。项目 AppID 为游客占位值，本地填写真实 AppID；私有工具配置不提交。
- 小程序配置 `TARO_APP_API_ORIGIN`（含 `/api/v1`）和 `TARO_APP_SOCKET_ORIGIN`，生产使用已登记 HTTPS/WSS 域名。
- 后端默认 `WECHAT_ENABLED=false`。凭据、超时和小程序版本选项见 `apps/server-elysia/.env.example`；真实 AppSecret 只由运行环境注入。
- 数据库仅提供增量迁移，保持原教师和历史积分引用。SQLite schema 由 canonical schema 同步。验证在临时数据库进行，未迁移用户数据库或生产。
- 实时适配遵循 Engine.IO v4 + Socket.IO `/realtime` 协议；后台断开，前台及重连补拉 REST 状态。喊话页仅在可见时每 3 秒刷新状态，隐藏时停止。协议测试不替代 Taro/微信真机验收。

## 验收记录

实际验证：

- 根 `typecheck --only`、`lint --only` 全部通过；`test --only` 共 99 项通过（后端 67、小程序 26、Web 6）。
- 根 `build --only` 的数据库、后端、Web、Taro 微信端四个构建通过。以测试域名构建后检查产物，包含指定 HTTPS/WSS 地址且无 localhost 默认值；缺少生产 API 配置时构建拒绝。
- SQLite 和 PostgreSQL schema 校验通过；绑定、邀请并发及 HTTP 测试使用隔离临时 SQLite，并执行完整迁移。未对真实 PostgreSQL 执行迁移。
- 85 条路由契约通过。覆盖身份冲突、邀请用途隔离/重发/撤销、失效身份、微信接口失败脱敏、积分重放、本人结果核查、会话竞态、切班与真实 Socket.IO heartbeat。
- 全仓格式检查及新增 Ant Design 控件检查通过。构建仍有原有 Web 大 chunk、共享 TS target 警告；现有 antd peer 警告未改动。

验证通过 `--only` 避免重复 Prisma 生成；Windows 上已有进程持有 Prisma DLL，依赖链接使用 `pnpm install --ignore-scripts`，未终止用户进程。已生成的客户端完成编译和临时数据库回归。

外部验收尚需真实微信 AppID/密钥、正式域名、开发者工具及 iOS/Android 设备。本次不是 PRD A01～A16 的全部真机验收；尚未执行微信平台发布、审核或旧 Web 退场。

## 团队路由

编码为 3 个 `gpt-6-luna / xhigh` Agent，分别拥有后端身份、运行时、页面目录；复杂身份和会话竞态另由 1 个 `gpt-6-sol / high` Agent 只读复核。主 Agent 负责 Web 入口、积分契约和整合验证。路由与采用结果记录在 `agent_team/teacher-miniprogram/state.json`；依当前平台要求使用任务内 Agent，没有创建独立聊天，无需聊天归档。

两个 Luna 编码 Agent 在收尾触及额度限制，主 Agent 采用其代码并完成修复和验证，没有继续派遣。累计 4 个 Agent，余 1 个预留名额未使用。
