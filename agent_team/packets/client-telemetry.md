# 任务身份

你是本任务的独立执行 Worker。禁止创建任何后台任务、线程或子 Agent。

## 目标与位置

- 总目标：完成 PRD 第一阶段 MVP。
- 你负责的子目标：实现低侵入客户端事件、显示端在线心跳、基础异常与 Trace ID。
- 该子目标在整体方案中的位置：等待后端事件契约阶段门后执行。
- 前置阶段门：后端事件 API 契约已确定。

## 交付物

- 产物：事件客户端、关键业务事件接入、大屏启动/页面/心跳、请求 Trace 传播与失败吞吐策略、测试。
- 写入路径：由主 Agent在阶段门后按未提交文件冲突重新分配。
- 返回格式：结论、变更或补丁建议、验证、风险。

## 边界

- 可读取：全仓库、PRD、后端契约。
- 可写入：仅主 Agent 后续明确分配的文件。
- 禁止触碰：所有当前未提交文件，除非主 Agent 后续明确接管并授权。
- 文件所有权：默认分析与新增独立文件；共享调用点由主 Agent 集成。
- reserved slots：2，由主 Agent 记录，Worker 不修改。

## 背景与约束

- 已知事实：工作区的 `display-surface.tsx`、`api-error.ts`、`realtime.ts` 等已有用户改动；采集失败不能影响业务。
- 用户偏好：保留现有交互，不扩展无关 UX。
- 关键约束：异步/尽力上报；最小必要数据；不记录学生个人信息、完整积分原因或自由文本；Trace 使用现有 requestId 机制；避免高频心跳产生无限数据。
- 与其他 Worker 的接口：消费后端事件 API；向主 Agent返回安全接入点清单。

## 验收

- 完成标准：大屏启动与在线、客户端类型区分、教师核心事件、异常与 Trace 可关联，且失败不影响业务。
- 必须运行的验证：目标测试/typecheck 和 `git diff --check`。
- 缺失信息时的处理：报告缺口，不猜测。
